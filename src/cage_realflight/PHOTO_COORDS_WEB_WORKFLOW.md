# 照片/人工坐标实飞网页流程

## 安全边界

`PHOTO_COORDS` 只是不使用两台外置地面 GPS A/B。K9 飞控自身 GPS、RC/H12、MAVROS、电池遥测和真实投喂器仍必须通过自检。网页不解锁飞机，也不自动切入 `AUTO.MISSION`；这两步始终由飞手使用 H12 完成。

控制优先级固定为：`H12 手控 > RETURN / 立即返航 > 普通自动任务`。

## 1. 启动前选择模式

打开 `http://NX3_IP:8080/`。每次停止系统后必须重新选择：

- `GROUND_GPS`：启动并检查地面 GPS A/B，提供中点和 A/B 对角网格；
- `PHOTO_COORDS`：不检查 `/dev/ttyUSB1`，不启动或等待 A/B，只允许数据库坐标任务。

输入模式在本次运行期间锁定。需要切换时必须先落地、解除锁定并停止系统。

命令行等价启动方式：

```bash
rosrun cage_realflight start_realflight_stack.sh \
  --input-profile photo_coords \
  --geometry circular \
  --feeding true \
  --rviz false \
  --web true
```

## 2. 建立网箱坐标

从实飞页进入“网箱坐标数据库”：

1. 创建大网箱；
2. 单个创建小网箱，按前缀、起始号和数量创建，或导入小网箱 CSV；每个大网箱总数最多 200 个；
3. 上传 JPG/JPEG，或输入人工 WGS84 纬度和经度，或导入坐标 CSV；
4. 照片绑定到一个小网箱；
5. 审核候选坐标并启用版本。

坐标 CSV 固定列：

```csv
small_cage_label,latitude,longitude,row_index,col_index,note
A-001,27.12345678,120.12345678,1,1,photo-20261105
```

照片海拔仅作为证据保存，绝不进入任务高度。任务 Z 值只使用网页的起飞、过渡和投喂相对高度。

## 3. 网页完成实飞流程

1. 查看顶部输入模式、FCU、机载 GPS、RC、电池、投喂器和飞行模式；
2. 在 `PHOTO_COORDS` 页面选择大网箱和一个或多个已审核小网箱；
3. 选择 HOME 最近邻顺序，或用上下按钮调整人工顺序；
4. 设置起飞/过渡/投喂高度、投喂秒数、航点停留、重复次数、速度、接受半径和最大航段；
5. 保证 `投喂秒数 < 航点停留秒数`；
6. 完成现场确认并开始 rosbag；
7. 生成预览，在可旋转、Z 轴向上的航点图中核对全部坐标和高度；
8. 点击“航点核对无误”。系统冻结 HOME、坐标版本、顺序和参数并保存任务快照；
9. 提交任务。只有页面显示上传校验成功、FSM=`WAIT_ARM`、飞控航点数量正确后才能继续；
10. 飞手用 H12 解锁，再用 CH5/E 手动切入 `AUTO.MISSION`；
11. 最后一个目标完成停留后，状态机关闭投喂器并请求、确认 `AUTO.RTL`。

## 4. RETURN / 立即返航

顶部 RETURN 始终可见，不依赖普通任务门控。飞机已解锁时点击后：

1. 立即关闭投喂器；
2. 作废剩余任务；
3. 请求 `AUTO.RTL` 并等待飞控模式确认；
4. 页面显示 `REQUESTED`、`RTL_CONFIRMED`、`MANUAL_OVERRIDE`、`FAILED` 或 `LANDED`；
5. 落地解除锁定后清除飞控残留任务。

FCU 断连或机载 GPS 无效时不会假报返航成功，页面会要求飞手接管。RETURN 后飞手切回 `POSCTL`/`ALTCTL` 等手控模式会立即锁定为 `MANUAL_OVERRIDE`，NX 不再重发 RTL。

飞机未解锁时点击 RETURN，只关闭投喂器、取消任务并清除飞控任务，不发送飞行模式命令。

## 5. 电量

页面直接显示 `/mavros/battery` 的百分比和总电压。飞控未提供有效 `percentage` 时显示“未知”，不会按电压推算。超过 3 秒未更新时显示“数据过期”。默认低电量阈值为 20%；自动任务中达到阈值会关闭投喂器并走同一条可确认的返航链路。H12 已接管时只保持投喂关闭和告警，不覆盖飞手模式。

## 6. 数据和升级

现场 SQLite 位于 `/home/nx3/cage_uav_ws/data/dji_gps/db/cage_site.db`。启动时检测顺序迁移，升级前自动备份到 `db/backups/`。旧航迹表和历史数据不删除，但网页和接口不再读取 DJI TXT、标准航迹 CSV 或航迹回放。

本仓库阶段只完成 GitHub 代码。部署到 NX3 前需要现场确认，然后在 NX3 编译并执行无桨测试。
